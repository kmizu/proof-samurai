# カーネル・型エラー解決ガイド

Proof Samurai が定義や証明を拒否するとき、その多くは論理的健全性（`False` が証明できないこと、および抽出コードが安全に動作すること）を守るための制約によるものです。代表的なエラーコードの原因と対処法を以下にまとめます。

## `K020` — 停止性エラー（構造的再帰ガード違反）

**原因:** `def loop(n: Nat): False = loop(n)` のような非停止関数を許すと、任意の偽の命題が「証明」できてしまいます。そのため、すべての再帰関数 `def` は、減少パラメータをパターンマッチして取り出した**構造的に真に小さい部分項**を再帰呼び出しに渡す必要があります。

**よくある誤り（部分項ではなく再構成した値を渡している）:**

```scala
// K020 で拒否される: List.Cons(nextHead, rest) は新規構成された値であり直接の部分項ではない
case List.Cons(head, tail) =>
  tail match {
    case List.Cons(nextHead, rest) => isSortedBool(List.Cons(nextHead, rest))
  }
```

**修正例（パターンマッチ済みの `tail` を直接渡す）:**

```scala
case List.Cons(head, tail) =>
  tail match {
    case List.Cons(nextHead, _) => isSortedBool(tail)
  }
```

## `K006` — 厳密正性（Strict Positivity）違反

**原因:** 帰納型 `Bad` が自身のコンストラクタの関数引数の左側（`case Mk(fn: Bad => False)`）に現れると、カリーのパラドクス（Curry's paradox）により体系が矛盾します。

**対処法:** コンストラクタ内で自身の型を関数型の引数側（`Bad => ...`）に置かないでください。一方、関数型の**戻り値側**（例: `case Lim(step: Nat => Ord)`）に現れる場合は厳密に正であり許可されます。

## `K025` — `Prop` から `Type` への不正な除去

**原因:** `Prop` に属する証明項はコード抽出時にすべて消去されます。計算用の関数（`Type`）が `Or[P, Q]` や `Exists[A, P]` の分岐を覗き見て `0` か `1` を返そうとすると、証明を消去した後の実行時コードではどちらの分岐を選べばよいか判定できなくなります。

**対処法:**
- 実行時の分岐が必要な場合は、`Or[P, Q]` ではなく `Type` に属する `Either[A, B]` を使用してください。
- 証人 `value: A` を実行時に取り出しつつ証明 `proof: P(value)` だけを消去したい場合は、`Exists[A, P]` ではなく `Subset[A, P]` を使用してください。
- なお、`False` と `Eq` は subsingleton であるため、`False` の除去（`absurd`）や `Eq` の書き換え（`rewrite` / `subst`）は `Type` への除去でも許可されます。

## `K005` — 宇宙レベル超過（`Type0` と `Type1`）

**原因:** `Type`（`Type0`）に属する帰納型のフィールドに、任意の `Type0` 型そのものを格納すると、非可述性によりジラールのパラドクス（Girard's paradox）を引き起こします。

**対処法:** 型を格納するコンテナ型には `: Type1` を明示してください（例: `enum TypeBox: Type1 { case Mk(inner: Type) }`）。

## `K026` / `E071` — 非網羅的な `match`

**原因:** コンストラクタの分岐が漏れていると部分関数となり、実行時クラッシュや論理的矛盾の原因になります。

**対処法:** 対象 `enum` のすべてのコンストラクタを網羅するか、ワイルドカード `case _ => ...` を追加してください。（`Vec[A](Nat.Succ(n))` のような添字付き帰納族では、`Vec.Nil` のように到達不能であることが証明できる分岐はエラボレータが自動的に処理します。）

## `T010` — 反射律（`refl`）の失敗

**原因:** `refl` は、等式 `lhs === rhs` の両辺が計算（正規化）のみで完全に一致する場合にしか成功しません。

**対処法:**
- `Nat` の代数等式（`+`, `*`, `0`, `Succ`）であれば `arith` を試してください。
- 関数定義の展開や `@simp` 補題の適用が必要なら `simp` または `simp(*)` を実行してください。
- 左右の辺にどの差が残っているかを確認するには、`refl` の代わりに `?check` を置いてゴールを表示してください。

## `T015` — 書き換え対象（`rewrite`）が見つからない

**原因:** ゴール側の定義がまだ展開されていないか、等式の向きが逆になっています。

**対処法:**
1. `rewrite(lemma)` の前に `simp` を実行して定義を展開する。
2. 右辺から左辺への書き換えである `rewriteRev(lemma)`、または双方向を試す `subst(lemma)` を試す。
3. 書き換えたい変数が `cases(x)` より前に導入された仮定に含まれている場合は、`cases(x)` の前に `revert(hypName)` を呼び出す。
