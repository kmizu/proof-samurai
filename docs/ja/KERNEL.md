# 信頼カーネルのアーキテクチャと健全性

Proof Samurai は **de Bruijn 基準（de Bruijn criterion）** に基づいて設計されています。構文解析、エラボレータ、メタ変数単一化、パターンマッチのコンパイル、タクティクスクリプト、自動探索（`auto`）、AI セッションのすべては**非信頼コンポーネント（untrusted）**として扱われ、すべての宣言と証明項は `KernelEnv` に登録される前に、小規模で独立した信頼カーネル（`samurai.kernel`）によって一から型検査されます。

## 健全性を支える 6 つの保証

1. **宇宙階層と可述性（`Sort.scala` / `TypeChecker.scala`）**
   - `Prop : Type(0)` および `Type(i) : Type(i + 1)` を採用し、`i <= j` に対して累積的部分型付け `Type(i) <= Type(j)` を持ちます。
   - `Type(i) : Type(i)` は拒否され、ジラール／ラッセルのパラドクスを防ぎます。
   - `Type(k)` に属する帰納型のコンストラクタ引数は `j > k` の `Type(j)` に属することができません。

2. **厳密正性検査（`Positivity.scala`）**
   - 帰納型は自身のコンストラクタ引数において矢印（`=>`）の左辺、任意の関数適用内部、および自身の結果添字に現れることが禁止されます。
   - 透過的な定義（例: `def Not(P: Prop): Prop = P => False`）は検査前に正規化展開されるため、別名経由の隠れた負出現によるカリーのパラドクスも防止されます。

3. **Subsingleton `Prop` 除去規則（`TypeChecker.scala`）**
   - `Prop` は `Pi` 型に対して非可述であり、定義的証明無関係性（proof irrelevance）を持ちます。
   - `Prop` 帰納型から `Type(k)` への除去は、対象が subsingleton（コンストラクタが 0 個の `False`、またはコンストラクタが 1 個ですべてのフィールドが `Prop` である `Eq` や `True`）である場合にのみ許可されます。
   - `Or` や `Exists` を `Type` へ除去する操作は拒否され、論理的無矛盾性とコード抽出時の健全な証明消去を同時に保証します。

4. **構造的減少による停止性検査（`Termination.scala`）**
   - すべての再帰項 `Fix(name, recArgIdx, ty, body)` は、`recArgIdx` 番目に帰納型の引数を取る必要があります。
   - `name` へのすべての再帰呼び出しは `recArgIdx` まで完全適用されており、減少パラメータのパターンマッチから得た構造的に真に小さい部分項を渡さなければなりません。
   - 未適用または非減少な再帰参照は拒否され、`def loop(n: Nat): False = loop(n)` を防ぎます。
   - NbE（`NbE.scala`）では、`Fix` の展開は減少引数がコンストラクタ値（`VCtor`）であるときに限られるため、正規化の停止性が保証されます。

5. **網羅性検査（`TypeChecker.scala`）**
   - コア言語の `Match` は、対象帰納型のすべてのコンストラクタを定義順に網羅する分岐を持たなければなりません。
   - 表面構文で到達不能コンストラクタを省略した添字付きマッチ（例: `Vec[A](Nat.Succ(n))` で `Vec.Nil` を省略）は、エラボレータによって判別モチーフ付きコア項へ変換されたうえでカーネルによる完全検査を受けます。

6. **公理・`sorry` の推移的追跡（`Env.scala`）**
   - `KernelEnv` は検証済みのすべての定義・定理について `axiomsUsed` を推移的に追跡します。
   - `--strict` チェックおよび厳密コード抽出は、依存関係内のどこかに `axiom` または `sorry` が含まれていた場合に失敗します。
